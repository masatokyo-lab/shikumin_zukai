# HANDOFF: 製造（チャット）× 品質検査（Code）の分業

作成 2026-09-26。Claude Code セッション（ブランチ `claude/probe-r1-execution-handoff-0fcj92`）から
claude.ai チャットへの引き継ぎ。Jev 品質ゲート全体の契約は `HANDOFF-jev-gate.md`（同じ Drive フォルダ）が正。

---

## 0. 結論（先に読む）

- **製造はチャット、品質検査は Code。** チャットは Jev を呼べない（zukai-jev MCP は Code のリポジトリ内でしか動かない）。
- **Jev は live で動作確認済み**（2026-09-26）。ただし閾値は**較正前**。判定は「参考値」で、品質の根拠にしない。
- 現時点で信用できるのは **g5（事実と推測・出典）だけ**。g6（記事構成）は人間が落とした記事を見逃した。
- 次の製造対象：**ジレット note の訂正反映**と、**新規「ネットワークビジネス」**。

## 1. 分業の契約

| 主体 | 責務 | やらないこと |
|---|---|---|
| チャット（製造） | 構成・執筆・図解・修正。根拠資料の収集と出典の対応付け | 合否の自己判定。「Jev で通るはず」と書くこと |
| Code（品質検査） | `jev_review` で検査し、群判定・修正指示（項目ID）を返す。結果を記録 | 本文の書き直し（指摘のみ返す） |
| 人間 | 最終判断。s7（独自性・一次経験）の確認。ルーブリックの較正 | — |

### 1.1 受け渡しの流れ

```
チャットで製造 → Drive に保存（本文 vN ＋ 根拠資料）
   → Code に「<ファイル名> を検査して」と依頼
   → Code が jev_review（article / diagram）→ 検査結果を返す
   → チャットで修正（項目IDごと）→ vN+1 を保存 → 再検査
   → 最大3周。エスカレーション（下記）で人間に戻す
```

### 1.2 チャットが Drive に置くもの（検査の入力）

| 置くもの | 形式 | 理由 |
|---|---|---|
| 本文 | Google ドキュメント or .docx。ファイル名末尾に版 `v1` `v2` … | 同じ記事の改稿を同じ run として追跡する |
| **根拠資料** | 別ファイル（`【根拠資料】<タイトル>`） | g5 群の裏付け判定に使う。**無いと g5 が効かない** |
| 図 | **SVG ソース、または図が示す内容の文章説明**を本文中に | Jev はテキストしか読めない。PNG / JPEG は評価されない（HANDOFF 3.4） |
| 種類の明記 | 冒頭に「article（図なし記事）」か「diagram（図解）」 | ルーブリックが違う。取り違えると空振りする |

フォルダは記事ごと（例：`01. ジレットモデル`、`02. ネットワークビジネス`）。

### 1.3 Code が返すもの（検査の出力）

- `verdict`（block / pass / unknown）と FAIL 群
- 修正指示：**項目ID**（例 `g5_source_granularity_gap`）＋確率＋該当の問い
- s7（一次経験の裏打ち）の参考値。**人間確認が必要**
- エスカレーション：`retry_limit`（3周到達）/ `stagnation`（FAIL 群が前周と同一）/ `oscillation`（新しい FAIL 群が出た）

### 1.4 チャット側の製造ルール（検査で落ちやすい所を先回り）

1. **数値ごとに出典を対応させる。** 記事末尾に出典を1つ挙げるだけでは不十分。「Picker を出典に挙げつつ、個別の数値は Picker に無い」が今回の FAIL 原因（`g5_source_granularity_gap`）。
2. **推測には推測と書く。** 「〜と考えられる（推測）」「筆者の試算」。無標の推測は `g5_unmarked_speculation`（critical）。
3. **換算・試算は計算根拠を書く。** 現在価値換算など。
4. **結論を先に。** `g6_no_conclusion_first` は critical。
5. **リスク・ダウンサイドを併記。** 経営判断に関わる記事では必須。

### 2.2 ジレット note 3版の検査（scope: article）

## 5. リスク・前提が崩れる条件

- **Goodhart：**製造側（チャット）がルーブリックに合わせて書くと、Jev は通るが中身が薄い記事に収束する。g6 が機能していない今は特に注意。
- **PASS 記事でも g5 で落ちる場合**、g5 の閾値 0.50 が厳しすぎる。案A の運用中にまずこれを確かめる。
- **Jev の一致度は約68%。**判定が割れるのは前提。s7 は必ず人間が見る。
- 事実の真偽は Jev では検証できない。g5 が立っても「間違い」ではなく「出典を確認せよ」の意味。
