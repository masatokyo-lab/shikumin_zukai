### 3.6 検査の層（挿入する本文）

> 1本の記事は ①本文 / ②図単体 / ③整合 の3層に分けて検査し、④公開判断は人間が行う。
>
> （上の4行の表をそのまま入れる）
>
> - ③を独立させるのは、g3 が本文と図の**組**の性質だから。本文だけ・図だけの判定からは較正できない。
>   7.4 の最良の境界事例（診断フロー→2列表）も g3。
> - ②に依頼内容と元資料を入れないのは、図だけが流通したとき（X など）に成り立つかを見るため。
>   ③に入れないのは、本文と図の関係だけを見る層だから。①は g5 の裏付けに元資料が要るので入れる。
> - 読者に見えないもの（冒頭の【検査用メタ】、「（画像ファイル：…）」、SVG の `<title>` 等）は state に入れない。
>   【検査用メタ】が冒頭にあると critical の g6_no_conclusion_first を誤って立てうる。
> - 反復の変更点（note）は記録に残すが state に入れない（較正の入力と本番の入力を揃えるため）。
> - 止めどき（2.3）は層ごとと、記事全体（FAIL を「層@図:群」で数える）の両方で判定する。
>   ①を直すと③が落ち、③を直すと①が落ちる往復を止めるため。
