# 生成 → Jev 検査（①②③）→ 不合格なら修正 / 全層合格なら④公開判断へ

生成したら必ず検査する。検査せずに「できました」と言わない。
検査器の出力は **合格（pass）/ 不合格（fail）の2値**。公開するかどうかは Jev ではなく**ユーザーが決める**。

設計の契約は `docs/HANDOFF-jev-gate.md`（層分割は付記 G）。この手順とそれが食い違ったら HANDOFF を正とする。

| 判定 | 人間が見るもの | Jev に渡す入力 | 問う群 |
| --- | --- | --- | --- |
| ① 本文 | 本文＋キャプション（図は隠す） | 同じもの＋依頼内容・元資料 | article 18問（s7 は人間確認） |
| ② 図単体 | 図1枚だけ | SVG のみ | g2 ＋ g5 |
| ③ 整合 | 本文全体＋図1枚 | 本文＋SVG 1枚 | g3 |
| ④ 公開判断 | 図入りの完成品 | **使わない** | —（ユーザーが行い、責任を持つ） |

## 0. モードと基準を最初に確かめる

`jev_ping` を呼ぶ。`layers` に ①（18問）②（8問）③（5問）が、`publication` に④は人間であることが返る。
`mode` が `stub` なら **スコアはダミー** なので、ユーザーに一行で伝える:

> Jev の APIキーが未設定（または呼び出せない）ため stub モードです。以下の判定は品質判断には使えません。

`live` でも、`warnings` に較正前の警告が出ている間は**この判定を品質の根拠として語らない**。
落ちた項目を直す材料としては使ってよいが、「Jev が通したから良い」とは言えない。

## 1. 図解・記事を作る

- 図解アーティファクトは `artifacts/<slug>.html`。単一 HTML、インライン SVG（`<figure><svg>…</svg><figcaption>…</figcaption></figure>`）、外部依存なし。
- note 記事は本文（`.md` など）と図（`.svg`）を別ファイルにしてよい。本文では図を「図3」のように呼ぶ。
- **図は SVG。** PNG/JPEG は Jev が評価できない。文字は `<text>` で書く（パスに変換すると読めない。matplotlib は `svg.fonttype='none'`）。
- **図のタイトルは描画の中に書く。** SVG の `<title>` / `<desc>` / `aria-label` は読者に見えないので Jev にも渡さない。
- **図の数値には、図の中で「試算」や出典を添える。** ②は図だけが流通したとき（X など）に成り立つかを見る。
- ライト/ダーク両対応、スマホ幅で読めること。**これはルーブリックでは検査されない**。自分で確認すること。
- Artifact として公開する場合は `artifact-design` スキルを先に読む。

## 2. `jev_review_all` で検査する

```
jev_review_all({ task, artifact_path, figures?, source_material, note })
```

- `figures` は本文と別ファイルの図: `[{ path: "figs/fig3_tree.svg", label: "図3" }, …]`。`label` は本文での呼び名。
  インライン SVG の HTML なら省略する（本文中の図をすべて使う）。図が見つからなければ警告が出て②③は回らない。
- `task` は依頼内容そのまま。`source_material` は元資料。**①の裏付け判定（`g5_*`）に要る。**②③には渡らない。
- `note` は前回からの変更点。記録に残るが Jev には渡らない。
- **返る `result` は記事全体の `pass` / `fail`。次にやることは `next_action` に入っている。**

| `next_action` | 意味 | やること |
|---|---|---|
| `fix_and_rereview` | どれかの層が不合格 | 3 に従って直し、`jev_review_all` で再検査 |
| `stop_and_escalate` | 回しても直らない（層ごと、または記事全体の上限・停滞・振動）か、判定不能 | **直さずに止めて**ユーザーに返す（4） |
| `hand_to_human` | ①②③すべて合格 | 5 に従って④公開判断をユーザーに渡す |

- `layers` に層ごとの結果（`blocking_fixes` が直す対象）、`failed` に「層@図:群」の一覧が入る。
- **`probability` は「欠陥が存在する確率」。高いほど悪い。** 逆に読まないこと。
- 1層だけ確かめ直すときは `jev_review({ layer: "text" | "figure" | "alignment", … })`。
  この場合の合格は `continue_other_layers`（④に渡すのは全層合格の後）。
- 旧 `scope` は使わない。`scope: "diagram"`（一括）は廃止でエラーになる。

判定不能（`fail_reason: "unknown"`、`missing_answers` が空でない）は不合格として返る。**直す対象が無いので回さずに人間に返す。**
回答が欠けたまま進むと群の欠陥数が実際より少なく数えられ、静かにゲートが緩む。

## 3. 直す

落ちた層の `blocking_fixes`（群がFAILしている項目）から先に直す。

| 落ちた層 | 直す場所 |
|---|---|
| ① 本文 | 本文。図に頼らずに読める書き方にする（①は図を隠して見る） |
| ② 図単体 | 図。タイトル・軸・単位・凡例を描画の中に。数値の注記も図の中に |
| ③ 整合 | 本文か図のどちらか。本文の問い・数値・呼び名と、図の中身を突き合わせる |

- `g5_*`（無標の推測、出典なき具体性、出典粒度の不一致、結論の誇張）が立った場合、それは
  **「出典を確認せよ」という指示であり「間違っている」という判定ではない。**
  Jev は事実の真偽を検証できない。確認は自分かウェブ検索で行う（`means` に同じ注記が入る）。
- 群の判定を無視して進めてはいけない（HANDOFF 禁止事項 #1）。
- `s7_originality` の判定を自分で上書きしてよいが、**上書きしたら必ず理由を書いてユーザーに見せる。**
  黙ったオーバーライドは禁止。

直したら `note` に変更点を書いて再度 `jev_review_all`。層×対象ごとの `run_id` は自動で引き継がれる。

**欠陥が前回より増えたら、その変更は捨てて前の版に戻す。** 反復は単調改善でなければ意味がない。

## 4. 止めどき（不合格のまま止める）

**止めどきはサーバーが `escalate` に入れて返す（`next_action: stop_and_escalate`）。自分で履歴を突き合わせない。**
層ごと（同じ層・同じ対象の前回）と記事全体（`round.escalate`。「層@図:群」の集合を前回と比べる）の両方で見ている。

| トリガー | 意味 |
|---|---|
| `retry_limit` | 反復が上限（3回）に達した |
| `stagnation` | FAIL群の集合が前回と同一。同じ場所を叩き続けている |
| `oscillation` | 前回になかった群がFAILした。**総数が減っていても止める** |

`oscillation` は項目間・層間のトレードオフ（本文を直すと整合が崩れる、など）をモグラ叩きしている状態。
回し続けても収束しないので、ルーブリックが合っていないか元資料が足りない。どちらかを述べて判断を仰ぐ。

判定は**群単位**で行われている（項目単位だと誤検出で毎回集合が変わり常時発火する）。
一方、修正指示に使うのは項目単位の ID。この二つを混同しないこと。

## 5. 全層合格したら④公開判断をユーザーに渡す

合格は「①②③で群単位の欠陥が見つからなかった」であって、公開してよいという判定ではない。
**公開するかはユーザーが決め、責任を持つ。** 記事ごとの重点（法規の記述、解釈の断定など）もここでユーザーが見る。
次の3つを見せて止まる:

1. **全層合格したこと**（stub なら「ダミー判定」、較正前なら「閾値は暫定」と必ず添える）
2. **`s7_originality` の人間確認**（`human_review`）。一次経験の裏打ちは Jev の死角（HANDOFF 禁止事項 #3）
3. **参考として残った単発の欠陥**（各層の `other_fixes`）。特に `g5_*` は「出典を確認せよ」として先頭に出す

ユーザーが公開判断を報告したら、`jev_ship` で記録する（**較正には使わない**）:

```
jev_ship({ artifact, decision: "ship" | "hold", round_seq, reason? })
```

- **ユーザーが言った値だけを渡す。** 推測で埋めない。報告が無ければ記録しない
- 公開しない理由が①②③の問い（本文・図単体・本文と図の整合）に当たるなら、**該当する層に `jev_label` を付けるか確認する**
  （どの層も拾えなかった欠陥＝ルーブリックの穴の候補）

## 6. 層ごとの人間の判定を記録する（較正の材料）

ユーザーが層ごとに判定を出したら、その層の検査の `seq`（`layers[].seq`）に `jev_label` で記録する:

```
jev_label({ seq, human_verdict: "pass" | "fail", group_labels?, boundary?, note? })
```

- **その層と同じものを見て付けた判定だけを記録する。** ①は図を隠した本文とキャプション、②は図1枚、③は本文と図1枚。
  図込みで読んだ感想を①に付けると、較正が狂う（人間は図で分かったのに Jev は図を見ていない）
- 判定を頼むときは、その層の見え方で見せる（①なら図を［図N：キャプション］にした本文、②なら図だけ）
- **ユーザーが言った値だけを渡す。** `group_labels` はその層で問う群だけ
- 返った `sample`（本文つき）は Drive「99. Jev連携/labels」に `<id>.json` で保存する。
  **このリポジトリは public なので、本文をリポジトリに書かない**
- `labels/ledger.jsonl`（本文なし）は commit / push する。クラウドのコンテナは消える
- ラベルは付けた版にだけ効く。本文や図を直したら、新しい版の検査に付け直す

## 7. 毎回ダッシュボードへ同期する

検査のたびに、スマホから見えるダッシュボードへ反映する。

1. `jev_feed({ since_seq })` を呼ぶ（初回は `0`、以降は前回の `next_since_seq`）。
2. 返った `records` を `ArtifactData` の `batch` で 1 回にまとめて書く:
   - collection `evals`、`doc_id` は `String(seq)`、中身はレコードそのまま（`kind: "review"` は1層、`kind: "round"` は記事全体）。
   - collection `status`、`doc_id` は `"current"`、中身は `state` に `mode` / `model` / `synced_at` を足したもの。
3. パネルの URL は README.md の表にある（`.jev/dashboard-url.txt` にも控えてある）。無ければ
   `dashboard/index.html` を `capabilities: {db: {}}` 付きで publish し、URL を両方に書いてユーザーに渡す。

`status` は毎回上書きする — これがスマホ側の「稼働中 / 待機中」表示になる。

## 禁止

- stub モードの判定を根拠に品質を語ること。
- 較正前の閾値による判定を「Jev が通した」として品質の根拠にすること。
- 検査を飛ばして完成を報告すること。①だけ・②だけで「合格」と言うこと。
- `s7_originality` の人間確認を飛ばして完成を報告すること。
- 合格を「公開してよい」と言い換えること。公開判断はユーザーがする。
- ユーザーが報告していない判定を `jev_label` / `jev_ship` に記録すること。
- 見るものが層と違う判定を `jev_label` に記録すること（図込みの感想を①に、など）。
- ④の公開判断を較正のラベルとして扱うこと。
- `jev_label` の `sample`（本文つき）をリポジトリに書くこと。
- 群の判定を黙って無視すること。オーバーライドは s7 のみ、かつ理由を明示して。
- 判定不能（`unknown` / `missing_answers`）を通過扱いにすること。
- `escalate` が返っているのに回し続けること。止めどきの判定はサーバーが済ませてある。
- 反復回数を戻すために `run_id` を新しくすること（ユーザーが仕切り直しを決めたときだけ）。
- `jev_decide` に「公開してよいか」型の質問を投げること。`jev_gate` を消したのと同じ理由。
- ルーブリックに通すためだけに図解から情報を削ること（`g4_*` の欠陥は消えるが
  `g3_figure_not_supporting` が立つ。立たなければ検査が甘い）。
- 図を PNG で渡すこと、図のタイトルを SVG の `<title>` だけに書くこと。
- 「公開してよいか」を Jev に訊くこと。この環境はその判定をしない（HANDOFF 禁止事項 #4）。
